1. Project Overview

The KDU Global digital platform consists of two tightly integrated applications:

  1. Public website — a modern React single-page application that presents academic programmes, graduate studies, engagement/clubs, research, admissions, and news.
  2. CMS backend — a PHP/MySQL content management system used by Super Admins, Heads of Department (HODs), faculty members, Graduate School staff, International Office, and club administrators to manage live content.

Static fallback content in the React app ensures the site remains usable if the API is temporarily unavailable. When the CMS is connected, published content and faculty profiles override or merge with those fallbacks.

Goals

  • One public brand experience for Kyungdong University Global.
  • Department pages that HODs can update without developer intervention.
  • Faculty profiles created once and listed under multiple programmes if needed.
  • Club pages managed by club admins created only by Super Admin.
  • Clear draft → publish workflow so unfinished edits never appear publicly.

Integration pattern

  • In development, Vite proxies /api and /media to http://localhost/kdu-backend/public.
  • Public pages use unauthenticated GET requests.
  • CMS login uses PHP sessions with credentials: 'include'.
  • Only published records are returned by public APIs.

3.4 Undergraduate departments

  • International Business Administration (API code iba)
  • English for Academic Purposes (API code eap)
  • Artificial Intelligence
  • International Hotel Management (API code ihm)

Each department page merges static content with live CMS data (hero, curriculum, faculty, news, events, admissions, contact) via useDepartmentLiveData.

3.5 Graduate school

The graduate experience is modelled after the official KDU Global Graduate Courses page (K-Global Graduate School of Business and Technology Convergence). It includes hero, dean message, programmes, course outline, curriculum components, careers, faculty, scholarships, and admissions steps. Sub-navigation mirrors undergraduate department UX.

3.6 CMS content on the public site

  • CmsContentProvider loads GET /api/site/content on app start and refreshes on window focus.
  • Home uses CMS headline, tagline, intro, CTA, and hero image when present.
  • About, Admissions, Contact, Navbar, and Footer consume CMS modules similarly.
  • Media paths such as /kdu-backend/public/media/… are normalized to /media/… for the Vite proxy.

4.4 Publish model

  • Draft — editable in CMS, invisible on the public website
  • Published — returned by public APIs; may set published_at
  • Archived — retained but hidden from public listings
  • Faculty profiles use is_published with an explicit Publish action
After publishing site content, refresh the React site (or wait for focus refresh) to see changes. The CMS success message reminds editors to open http://localhost:5173.

4.6 Faculty multi-department affiliations

A faculty member creates one profile. Through faculty_profile_affiliations they can appear under multiple undergraduate departments and optionally under Graduate School.

  • Home department remains on the user/profile for HOD ownership.
  • Additional departments are selected in the Faculty Dashboard or when creating the account.
  • Public lists: /api/{department}/faculty and /api/graduate/faculty.

4.7 Clubs CMS

  • Only Super Admin / Root creates clubs (Manage clubs).
  • Root then creates a club_admin user assigned to that club.
  • Club admins edit only their club profile, news, and events, then publish.
  • Frontend engagement club pages merge published API clubs with static fallbacks.

7. Operational Workflows

7.1 Super Admin publishes Home content

  1. Sign in to CMS as Root.
  2. Open Website content → Home Page.
  3. Edit headline, tagline, intro, CTA, and upload a site hero image.
  4. Click Publish.
  5. Refresh the public site at http://localhost:5173.

7.2 HOD manages a department

  1. Sign in as HOD (account linked to one department).
  2. Edit department pages, news, and events; publish when ready.
  3. Create faculty accounts under Faculty accounts (optionally tick extra departments / Graduate).
  4. Faculty log into the Faculty Dashboard to complete and publish their profile.

7.3 Faculty multi-programme listing

  1. Faculty opens Faculty Dashboard → Profile.
  2. Under Departments & programmes, tick every programme where they teach.
  3. Optionally tick Also list under Graduate School.
  4. Save and Publish — one profile appears on each selected public faculty list.

7.4 Create a club and club admin

  1. Root → Manage clubs → create club.
  2. Root → Users → role Club Admin → assign club → temporary password.
  3. Club admin signs in → My club page / news / events → Publish.

9. Installation & Local Development

9.1 Prerequisites

  • XAMPP (Apache + MySQL/MariaDB)
  • Node.js 18+ (recommended 20/22)
  • PHP 8.2+
  • Git

9.2 Backend setup

  1. Place the backend at C:\xampp\htdocs\kdu-backend.
  2. Start Apache and MySQL in XAMPP Control Panel.
  3. Create database kdu_backend if needed.
  4. Run migrations: 
    mysql -u root kdu_backend < database/install.sql
  5. Copy .env.example to .env and set DB credentials, CORS origin http://localhost:5173, and mail settings.
  6. Create Root user: 
    php scripts/create_root.php admin@kduglobal.edu "YourStrongPass123!" "Super Admin"
  7. Verify: open http://localhost/kdu-backend/public/api/health
  8. CMS: http://localhost/kdu-backend/public/cms/

9.3 Frontend setup

cd "C:\Users\Mascud Mohamed\kdu-global-website"
npm install
npm run dev

Open http://localhost:5173. Leave VITE_API_URL empty in development so the Vite proxy handles API calls.

10. Deployment Notes

  • Build frontend with npm run build; host dist/ on a static web server or CDN.
  • Set VITE_API_URL to the public backend origin before building.
  • Point Apache/Nginx document root (or alias) at kdu-backend/public.
  • Ensure mod_rewrite is enabled and public/.htaccess is respected.
  • Make storage/uploads writable by the web server user.
  • Configure HTTPS and restrict CMS access if exposed publicly.
  • Align CORS allowed origins with the production frontend URL.

11. Troubleshooting

SymptomLikely cause / fix
CMS shows Published but site unchanged Hard-refresh frontend; confirm /api/site/content has non-empty published fields; ensure Home maps hero/intro.
Broken image in CMS preview Use Upload (stores /media/…); avoid pasting full XAMPP browser paths; confirm file exists under storage/uploads.
Faculty photo appears as home hero Do not reuse faculty media for site hero; site uploads go to media/site/.
MySQL ERROR 2002 Start MySQL in XAMPP.
Import path / Vite resolve errors Check relative imports from src/pages/ use ../ not ../../.
Faculty not listed on second department Ensure affiliations saved and profile published; check faculty_profile_affiliations.
Club admin cannot be created Create the club first under Manage clubs, then assign club_id.
Security reminder: Never commit real .env credentials or production passwords. Rotate temporary passwords after first login. Keep Root accounts to a minimum.
